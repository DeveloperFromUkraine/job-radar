## Resolution

The salary rule regressed in three rounds running, each fix tipping it towards the opposite mistake. The owner chose a principled fix rather than another patch:

- **H-01, bias to pay.** This follows the spec's priority: a wrong "no salary" reason is the sharpest failure (§1), and a false pay reading only avoids a lowering (§6.1).
  - A pay word before the amount always wins.
  - Only the words right after the amount, up to `and` / `with` / `,` / a line break, can name it a perk.
  - A later amount-naming perk noun (budget, stipend, allowance, reimbursement, voucher) rejects it only when no pay word comes before the amount.
  - Add-ons (equity, bonus, stock) never reject it.
  - `\n` and `•` end a clause on both sides.
- **The labelled set becomes the guard.** Every probe from all three review rounds goes into `pay-fixtures.ts` as checked rows, so this kind of case is covered from now on.
- **H-02 and H-03: fix both.**
  - An uppercase 3-letter code next to a number is a currency.
  - A pay word before a bare amount counts.
  - The perk nouns are added.
